# Answering study, November 2026

Does an AI agent find, check and cite facts better from an AgenticSystemCore node than from plain web pages, pages plus `llms.txt`, or ordinary retrieval (BM25 over the same Markdown)? This folder holds the question set, the harness, the raw rows and the report. Start with `REPORT.md`; the choices behind the harness are in `DECISIONS.md`. The repository README (`../README.md`) says where the inputs come from and how the figures on the benchmarks page map to these files.

## Re-run everything

```sh
cd answering
bash run-all.sh
```

The script is resumable: rows already in `results/*.jsonl` are skipped. Delete `results/runs-*.jsonl` to start from nothing (the hosted-model rows cost money to make again; see below).

## Requirements

- Linux, Node 22.13 or newer (the reference run used 24.18), Python 3, `rsync`, `npm`.
- The engine at tag `v1.1.0` with `npm ci` run in it, and clones of the two node repositories at the commits named in `../README.md`. Set `ENGINE_DIR` and `NODES_DIR` if they are not next to this repository. `src/setup.sh` copies what it needs into a scratch folder; no repository is written.
- Ollama on `127.0.0.1:11434` (`ollama serve`) with `qwen2.5-coder:7b` and `gemma3:4b` installed. No remote model is used for the local rows.
- `BENCH_SCRATCH`: scratch folder (default `${TMPDIR:-/tmp}/agsc-benchmarks/answering`).
- A 6 GB GPU or better; the reference run used one GPU with 6 GB, 16 cores and 31 GB RAM. About 6.5 hours of wall time for the local models.

## Layout

| Path | What |
|---|---|
| `questions/q-authored.jsonl` | the 60 questions as written, with gold items and gold facts |
| `questions/questions.jsonl` | the same plus two paraphrases each (the frozen set) |
| `questions/FROZEN.sha256` | hash of the frozen set, taken before any run; `node src/freeze.js --check` verifies it |
| `src/` | the harness: `corpus.js` (pages, items, chunks), `conditions.js` (C0-C4), `agent.js` (tool loop), `prompts.js`, `retrieval.js` (BM25), `scorer.js`, `runner.js`, `stats.js`, `report.js`, `nomodel.js`, `handcheck.js`, `transcript.js` |
| `tests/` | scorer tests on fixed examples: `npm test` |
| `results/runs-*.jsonl` | one raw row per question, condition, model and seed |
| `results/nomodel.json` | bytes and tokens read per fact, and retrieval recall, no model |
| `results/handcheck.jsonl` | the hand-check verdicts; `handcheck-c3c4-leniency.md` is the leniency check |
| `reports/` | generated tables (`tables.md`, `summary.json`), `final-template.md` (the prose of `REPORT.md` with `{{table}}` placeholders), two example transcripts |
| `REPORT.md` | generated by `node src/report.js` from the template and the rows |
| `paid-run.sh` | the run on two hosted models (needs `LLM_API_KEY`) |

The question rows carry an `author` field that names the model that wrote them. It is part of the frozen file and stays as it is.

## Single steps

```sh
node src/freeze.js --check                      # the question set is the frozen one
npm test                                        # scorer tests
node src/nomodel.js                             # bytes and tokens per fact, no model (about 10 s after setup)
node src/report.js                              # rebuild REPORT.md and the tables from the rows
node src/runner.js --model qwen2.5-coder:7b --conds C2,C3 --seeds 1 --only q05,q29   # a few runs
node src/handcheck.js agree                     # agreement of the hand check with the scorer
```

`node src/report.js` ignores `BENCH_NUM_CTX`: the local-model rows ran at 8,192 tokens and the truncation table of section 4 depends on that.

## Hosted models

The runner talks to any OpenAI-compatible `/chat/completions` endpoint when `LLM_BASE_URL` is set. The key comes from the environment only; no file is read for it. `LLM_TOKEN_BUDGET` is a hard cap on prompt plus completion tokens for the whole process: the call that would pass it is refused and the run stops with exit code 3 (finished rows stay on disk; run the same command again to continue after raising the cap).

```sh
export LLM_API_KEY=...                 # your provider's key, typed in the shell; never written to a file
export LLM_BASE_URL=https://openrouter.ai/api/v1     # optional; this is the default of paid-run.sh
bash paid-run.sh                       # the two runs of the report, with their token caps
```

or one run by hand:

```sh
export LLM_TOKEN_BUDGET=3500000 BENCH_NUM_CTX=32768 SOURCE_DATE_EPOCH=1767225600
node src/runner.js --model <model-name> --conds C0,C1,C2,C2b,C3,C4 --seeds 1
node src/report.js
```

Check the temperature and seed support of the provider: a provider that ignores `seed` makes the three seeds three samples of one wording.
