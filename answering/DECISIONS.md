# Method decisions (17 and 18 Nov 2026)

Each line: the choice, then why. None was tuned on results; the few harness changes after the smoke run are listed at the end.

## Corpus
1. **Built output, not a fresh build.** `agsc build` of a copy of the demonstration node fails with AGSC-E901 (the home page links `/ledger.jsonl` and `/changelog/`, which need the site pipeline's git-log file). The committed `www/` of both nodes (built with engine 1.1.0 on 13 Nov 2026) is copied to a scratch folder and used for C0, C1 and the no-model measurements.
2. **Published items only.** Demonstration node: 50 published concept items + 20 clusters (`publish-set.json`). Main site: 14 concept/procedure items + 3 clusters. The question set uses items only.
3. **`agsc mcp` serves held-back drafts.** Run on a copy of the source, it returned draft items that are not on the site. For C2 and the Markdown corpus the scratch copy has the 103 draft files deleted, so C2 sees the same items as the site. This is a finding about the node, reported in REPORT.md.
4. **The main site is bigger than its items.** C0 and C1 may also reach the specification and docs pages of the main site; C2, C3 and C4 see only the items. Unanswerable questions about the main site were chosen to be absent from the whole build (grep-checked).
5. **Gold unit = item (slug),** not chunk. The node's chunk ids are 64-digit hashes that no agent writes in an answer; items are what the question text and the tools name. Chunks are used only for the no-model byte count and for C3 (chunks = one per `##` section of the Markdown).

## Questions
6. 60 questions: 40 one-item, 10 two-item, 10 unanswerable (7 on the demonstration node, 3 on the main site; 28+12 one-item, 7+3 two-item). Written by the model Claude (Sonnet 5.5) from the item texts; no outside annotator. The same-author limit is stated in REPORT.md.
7. Gold facts are regular expressions (case-insensitive); all must match. Checked mechanically against the gold items' text and against every wording of the question (`src/freeze.js`): no fact is readable from a question.
8. `gemma3:4b` made two paraphrases per question (seeds 10, 11, temperature 0). A paraphrase is kept only if it holds every number, code-like token and named entity of the original; otherwise the original wording is used and the row says `original-fallback` (14 of 120).
9. **Seed = wording.** At temperature 0 a seed changes almost nothing, so seed 1 runs the original wording, seed 2 the first paraphrase, seed 3 the second. The same wording is used for every condition. Seeds and wording are therefore confounded; the report gives per-question means over seeds.
10. Question set frozen (SHA-256 in `questions/FROZEN.sha256`) before the smoke run and the full run. The smoke run used 6 of the 60 questions. The scorer was changed once after the smoke run (below); questions never.

## Conditions and limits (identical for all)
11. Model `qwen2.5-coder:7b`, temperature 0, `num_ctx` 8192, answer limit 400 tokens, tool results cut to 3500 characters, at most 8 tool calls, top-5 passages for C3. (A first attempt with 16384 and 5000 ran at about 100-200 s per tool run because 27 % of the model sat on the CPU, and was stopped after 12 rows; the rows are not part of this package. The harness also stops tool calls when the prompt nears the context, so Ollama never drops the start of a prompt. Ollama was restarted once with flash attention and an 8-bit KV cache; it did not change the GPU share, the setting stayed on.)
12. **C2 exposes four of the ten tools** (search, read, links, ask), to keep the contract testable. A seven-billion-parameter model with ten tools is not a fair test of the contract, and the other six write or compose.
13. **One long-lived `agsc mcp` process per node** for the whole run; its tools are read-only, so nothing leaks between runs. Start-up time is not in the wall time.
14. **Closing turn.** With the answer rules (including `NOT_IN_CORPUS`) in the system prompt, the model refused at once without looking (smoke test, 0 tool calls in 15 of 15 tool runs). So for C0-C2 the system prompt only describes the tools; when the model stops calling tools, one closing user message gives the answer format. C3 and C4 get the same format in their single prompt. The extra turn is counted in the tokens and time.
15. Models that print a tool call as JSON text (qwen2.5-coder does this part of the time) are read as tool calls, for all conditions.
16. **C4 (paste everything)** gets the corpus in slug order, cut to the context limit minus 1,500 tokens: 28 of the 50 demonstration items fit (6,667 tokens), the main site's 14 items fit entirely. This is the 'truncated to the context limit' baseline; the cut falls on the alphabetical end of the corpus, so the result depends on which items the questions touch (section 4 of REPORT.md).
17. **C3** uses MiniSearch 7.2.0 (BM25 family), default scoring, OR over terms, a short English stop list, no tuning, over Markdown chunks split at `##` headings.
18. **gemma3:4b** has no tool calling in Ollama, so it runs C3 and C4 only.
19. Run order: seed 1 of everything, then the cheap conditions for all seeds and both models, then seed 2 of the tool conditions. Seed 3 of the tool conditions (C0, C1, C2, C2u, C0h, C1h) was not run: seeds 1 and 2 gave 0-13 % correct and a third wording would add about 240 runs (80 minutes) without changing the reading. Stated in REPORT.md section 7.

## Scoring
20. Correct = every gold fact matches and the answer is not an abstention. Abstention = the token `NOT_IN_CORPUS` or a plain refusal phrase in the first 200 characters.
21. Cited = the item is named in the `Sources:` block (slug or exact title) or by an item URL anywhere. A bare word like "link" in running text is not a citation (this matters: five main-site items have common words as slugs). Two-item questions: `cited_all` needs both.
22. Verifiable = the answer carries a hexadecimal digest (16+ digits) that is a prefix of a gold chunk's digest or id. No condition's tools return a digest to the agent (see REPORT.md), so it is reported as a capability, not accuracy.
23. Statistics reuse the engine's `bench/metrics.js`: bootstrap (10,000 resamples, seed 1, questions as the resampled unit, per-question mean over seeds), sign-flip permutation test, Holm correction. Exact two-sided sign test added in `src/stats.js`.
24. Hand check: 30 random rows (fixed seed) judged by Claude, not by an independent person; agreement in REPORT.md.

## Changes after the smoke run (harness defects, not results)
- MiniSearch import (CommonJS entry), prompt restructure (item 14), a `Sources:` list on later lines now counts (item 21; found because C3 answered with a bulleted list).

## Added during the run (17 Nov, after 77 seed-1 rows); declared BEFORE the runs below were made
25. **Diagnosis of the 0 % tool conditions (C0, C1, C2).** From the raw rows (seed 1, 16-17 questions): the first tool call was the home page "/" in 0 of 17 C0 runs although the prompt says to start there; 70 % of tool calls repeat an earlier call with the same arguments; the model reached the gold item's page or `read` in only 5 of 50 tool runs and abstained in all 50. Tool results do reach the model and the closing turn is always reached (every row has an answer). A direct replay (a throwaway script, not kept) of one run where the model had read the right item showed: with the node's JSON envelope as the tool result the model answers `NOT_IN_CORPUS`; with the same item body as plain text it answers correctly. So the cause is two things, neither a harness defect: the 7B model cannot drive a tool loop (repeats, ignores instructions, abstains), and the node's `read` output (JSON envelope, escaped newlines, chunk metadata) is hard for it to read. Context truncation is guarded (the harness stops tool calls before the prompt outgrows 8,192 tokens; `context_stop` is recorded; 19 of 50 tool runs hit it). Rows are therefore kept, not discarded. Two example transcripts are in `reports/` (made by `src/transcript.js`).
26. **C2u (added).** Same four node tools through the same server, but the host shows the model the content instead of the JSON envelope (`unwrap` in `src/conditions.js`). It tests whether the failure is the output format. Reported separately; never merged with C2.
27. **C2b (declared before its runs; the like-for-like of C3): "node tools, one shot".** The harness, not the model, calls the node's `search` once with the question as written for the run, takes the first five hits, calls `read` on each, and puts in the prompt for each item: slug, IRI, the item body (cut to 1,400 characters), and the digests (first 16 hex digits) of its chunks. No tool loop; same answer limit and same answer format as C3, plus one sentence that is only possible here: "cite as slug (digest)". Items, not chunks: the node's `read` returns whole items. Reports the digest-verified citation. Reported next to C3 as the like-for-like pair; never merged with C2.
28. **Hand check of C3/C4 leniency**: 10 C3/C4 answers read against the gold facts; result in `results/handcheck-c3c4-leniency.md`.
29. **Hosted models.** The runner accepts an OpenAI-compatible endpoint from environment variables only (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` via `--model`, `LLM_TOKEN_BUDGET` as a hard cap on prompt + completion tokens for the whole process). No `.env` file is read. `paid-run.sh` shows the command.

## Added after the full pass (18 Nov); declared BEFORE the runs below were made
30. **Finding: C0 and C1 as first built do not "start from the home page".** The design says C0 starts from the home page with its links visible. The first harness only told the model to start there; in 0 of 240 runs did it do so (it guessed URLs such as /concepts/graph-frameworks, which do not exist). That is a deviation of the harness from the design, not only a model weakness. The first results stay in the report (as C0 and C1, "model must open the home page itself").
31. **C0h and C1h (added).** Same as C0 and C1, but the harness fetches "/" itself and puts the text in the conversation as the first tool result before the model's first move (cut to the same 3,500 characters; the navigation links are at the top of the page). The harness call does not count against the 8 calls; its tokens are counted. Same questions, seeds 1 and 2, same everything else. C2 has no matching step (the node has no home page for tools), so C2 is unchanged. Reported next to C0 and C1; never merged.
32. **Harness defect found in C2b, rows discarded and re-run.** `system()` in `src/prompts.js` listed C3 and C4 as the conditions that carry the answer format in their prompt, and C2b was left out by a failed string replacement. So C2b ran without the "Sources:" and `NOT_IN_CORPUS` rules in its first (qwen2.5-coder:7b 180 rows, gemma3:4b 180 rows) pass: low citation (6 %), low abstention (60 % and 27 %). Those 360 rows are not in any table and are not part of this package. C2b is re-run with the fixed prompt, all seeds, both models. Found while checking C0h; C0-C4 were not affected (checked: the system prompts of C0, C1, C2 carry no format by design, C3 and C4 do).
33. **Wall-clock defect.** The machine's clock moved backwards during some runs (a clock adjustment), giving negative `wall_ms` on a few rows. Rows are kept; the seconds column uses only rows with a positive wall time (count in REPORT.md). Seconds are also unreliable for another reason: another process on the machine (a test run of a different repository) shared the CPU for part of the first pass.
