# Method decisions

Study of 18 Nov 2026. Each choice below has a reason and a way to undo it.

## Scope and method

1. **Cases: 14 candidates, split into 16 result files, plus case 15.** Each candidate exists in the code or the docs of the engine at tag 1.1.0. Case 8 has two parts (writes, injection) because they use different methods. Case 15 (the graph read by independent RDF tools, `src/case15_semantics.py`) was added after the report of the first 14 was generated; its section is written by `src/report.js` from `results/case15-semantics.json`.
2. **Verdict words.** `win` and `loss` only where both sides ran the same task. `capability difference` where the alternative has no mechanism at all. `tie` where both sides do it. `cost only` where no like-for-like alternative was measured (case 5). A capability difference is never reported as an accuracy result.
3. **No estimates.** Every number in `REPORT.md` is read from `results/*.json` by `src/report.js`. A case that could not be measured says so and gives the reason.
4. **Engine copy.** The released engine (tag v1.1.0, `ENGINE_DIR`) is copied to scratch and run from there, so no file of the repository is touched. `src/setup.sh` does the copy.
5. **Nodes.** Built sites are copied from the repositories as committed (`www/`). For rebuilds the repositories are copied with their git history, because the ledger and the changelog are derived from the git log (the engine refuses to build the patterns node without it, error AGSC-E901). Reading history writes nothing. No git write command was run in any copy.
6. **The main node builds through its own pipeline.** `AgenticSystemCore.com` calls the engine from `scripts/build.js` with `SITE_ENGINE`; `agsc build` alone fails there (AGSC-E901, no security.txt in the Bundle root). Case 3 uses the pipeline for that node and `agsc build` for the patterns node.
7. **Clock.** `SOURCE_DATE_EPOCH=1767225600` everywhere. Seeds are fixed (20261118 unless the case names another).
8. **Local models only.** Ollama on 127.0.0.1, `qwen2.5-coder:7b` and `gemma3:4b`, temperature 0, seed 1, 16,384-token context (the answering study used 8,192; the blueprint Bundles of case 6 do not fit in 8,192). Only case 6 uses a model.
9. **Reused code.** `src/shared/` holds copies of the answering study's `corpus.js`, `retrieval.js`, `scorer.js`, `stats.js`, `llm.js`, with a new `config.js`. The answering study's rows are copied to scratch before reading (case 2, case 11).

## Per case

10. **Case 1 (tamper).** Damage is applied to a copy of the built patterns site: 20 random files per class (pages, per-item copies, other files) and all 9 files the discovery document names, with four kinds of damage (one byte, one sentence, a truncated file, a swapped file) plus stale files from another build and a whole older site. Detector: the engine's `validate-wellknown --level 2` and the same check in the Python package from PyPI. The plain-pages, `llms.txt` and BM25 alternatives publish no digest, so a client with no earlier trusted copy has no check; that is counted as 0 and labelled as "no mechanism". The strongest alternative is a Markdown folder under git with a known-good commit; it is measured with `git hash-object` (writes nothing) and reported beside the node. A client holding an anchor file (`agsc-host verify-anchor`) is measured for the whole-older-site case.
11. **Case 2 (citations).** The answering study's rows are re-scored mechanically at three levels (names the item; locator a program resolves; published digest of a passage that holds the facts). The `runs-anthropic_*` file was still being written; its row count at copy time is recorded and the numbers describe the rows present, not the finished run.
12. **Case 3 (reproducible build).** Two builds in two clean copies, then single changes (build instant, time zone, locale, folder path). The alternative measured is a BM25 index built twice.
13. **Case 5 (time to first node).** The documented quick start of `docs/guides/mode-0.md`. The guide's `git init` and `git commit` are replaced by `SOURCE_DATE_EPOCH`, which the guide names as the alternative, because this study runs no git write command. Whether an error message names the fix was judged by the author after reading each full message (a word search was tried and dropped as too loose).
14. **Case 6 (typed links).** The two published nodes use only the `related` key (patterns: 50 of 50 items; main: none), so they cannot carry a question about "depends on" or "supersedes". The questions use the engine's three worked blueprint Bundles (`examples/blueprints/`, 71 items) which use `requires`, `uses`, `verifies` and `decided-by`. These are example Bundles written by the project, not live nodes; the report says so. Gold comes from `graph.nq` of each build, so the program systems read the same source as the gold; they are shown as a capability, not as accuracy. The retrieval side gets two tries (question text; question text plus the subject's slug) and the whole raw Markdown file, front matter included. Questions are generated from the graph by a seeded script, not hand-written, to avoid choosing easy ones.
15. **Case 7 (cross-node).** Ten questions, each with one fact in each node; every gold fact is checked against the published text before anything runs. No network: host names are mapped to the two build folders. Retrieval is the same BM25 on both sides so the case measures finding the peer and attributing facts, not ranking.
16. **Case 8 (governance).** Part A: 20 inputs to `propose` and `remember` (10 each, hostile ones included) plus one call to each of the eight other tools; the whole Bundle folder, git data included, is hashed before and after. Part B: 30 injection samples written for this study (15 structural, 15 subtle) and 10 harmless controls, each put in one item of a small Bundle and linted. A five-line phrase search (whitespace tolerant) is the baseline, because plain folders and RAG indexes have no scanner and a baseline of nothing would be unfair to the reader's judgement. The samples were written by the author, knowing the rule's list; the subtle half is deliberately outside it. That makes 0 of 15 expected; the number shows the boundary, not a ranking of products.
17. **Case 9 (held-back content).** Run on the full copy of the patterns node (drafts present). The control is the published-only copy.
18. **Case 10 (scale).** The engine's own generator (`bench/gen-bundle.js`), not a new one: it is deterministic (output is a function of the item count), valid per the schema, and the same generator behind the engine's published build curves. Three build runs per size, median. Memory from GNU `time`. Search latency: median of 30 queries made of words taken from the generated items (seeded). The BM25 baseline is one Node process, index built in memory.
19. **Case 11 (reading cost).** Routes C0 to C4 come from the answering study's `nomodel.json` unchanged. Route D (bare domain, discovery document, chunk file, BM25) is new and run here.
20. **Case 12 (round trips).** Compared over published items only; a key counts as kept when its text is equal after whitespace folding. Steering, Mermaid and SKOS exports are not pairs (no import of the same shape) and are listed as such.
21. **Case 14 (offline).** `unshare -rn` (new user and network namespace). The result file records that an outbound connection fails inside it. Only loopback is brought up, for the HTTP transport of the tool server.

22. **Case 10 was run twice.** The first run overlapped with light jobs of other cases; the recorded run is the second, alone on the machine.
23. **Case 9 reads the source folder of the patterns node, drafts included.** This is the point of the case (the local tool server serves held-back items). The results keep counts only, no draft text.
24. **`run-all.sh` was not run end to end in one pass.** Each case script was run in its final form, one at a time, and `run-all.sh` lists them in the same order. A single full pass (about 45 minutes) has not been done.

## Not measured, with the reason

- Embedding or vector RAG: no embedding model is installed locally and no remote model was called. Every "RAG" in this study is BM25 (MiniSearch), the same as the answering study.
- Case 6 with a model that calls the node's tools: the answering study found small local models do not drive the tool loop; it was not repeated.
- `agsc-host serve` over a real network, and the browser pages: out of scope (offline, no browser).
- The WebAIAssist extension: not opened.
