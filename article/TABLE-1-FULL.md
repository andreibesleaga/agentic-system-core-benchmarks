# Supplementary material: Table 1 in full

For the article "Documentation Becoming Knowledge That AI Agents Can Cite and Readers Can Check" by Andrei N. Besleaga,
submitted to IEEE Software. The article prints a short version of Table 1; this is the full table, with the evidence
for every row. Reference numbers in brackets are those of the article. The figures can be recomputed from the
benchmarks repository, https://github.com/andreibesleaga/agentic-system-core-benchmarks (`node verify.js`), and
from the reports named in its README.

*Table 1 (full). Problems that agents and teams meet today, what the format does about each, and the evidence.*

| Problem today | What the format does | Evidence |
|---|---|---|
| An agent cannot tell what a site offers, or in what form | One discovery document at a well-known address [6], [7], with a profile registered at IANA [9] | A second checker, written separately in Python, rejects the same 40 of 40 damaged documents with the same error codes; from a bare domain the document brings one fact into reach at 1,587 tokens, against 4,488 by crawling the pages |
| A cited page changes and nobody notices | A digest for each machine file and each passage [8]; the citation carries it | 33 of 33 changed files caught; the covered files hold every sentence of every item; a digest of 14 October exposed a change made since |
| A citation points at a whole page, or at the wrong one | Every passage has its own address | The read call returned the passage with its digest in 50 of 50 cases; through the tools Haiku cited every needed item in 97 % of answers, against 58 % from plain pages |
| Agents answer wrongly from pages, at a high token cost | Ten tools over the Model Context Protocol [11]: search, read, ask, links, explain, compose, check, brief, propose, remember | With four of them (search, read, links, ask): 92 to 98 % correct against 60 to 67 % from plain pages, at about half the tokens; on questions that need two items, 100 % against 50 % |
| An agent gives up although the answer is there | Search that lists the items, and a read call that returns their text | The search listed every needed item for 50 of 50 questions; Haiku wrongly said "not found" on 1 % of answerable questions through the tools, 22 % from plain pages |
| Small local models cannot run a tool loop | Passages published as one file, ready for a keyword index | Given the site's own search and read results in one prompt, a 7-billion-parameter model answered 84 %; with a keyword index over the Markdown, 94 % at 770 tokens an answer |
| Text does not say how things relate | Typed relations in a graph under an ontology (RDF, SKOS, PROV, Dublin Core, SHACL, SPARQL) | Relation questions: retrieved passages 16 to 21 %, pages built from the graph 70 to 77 %, graph tools 58 %; cards related to both of two cards: graph tools 24 of 24, pages 11 of 18; shape checks pass on 5 of 5 graphs; 8 of 10 published queries run as written (the other two take a selection as input) |
| An agent invents an answer when there is none | Tools that return what exists, and relations that can be listed in full | No fitting card: said so 22 times in 24 through the graph tools, 11 of 18 from pages; unanswerable factual questions: Haiku and DeepSeek abstained on 10 of 10 through the tools in both sets |
| Agents change content without control | Every write is a proposal that a person accepts | In 20 attempts through the tool server no source file changed: 8 returned a proposal for a person, 12 were refused with an error code |
| Unfinished drafts reach agents | Only published items reach the machine files and the page tools | 0 of 103 drafts on the published files; the local tool server serves them, a copy of published items serves none |
| Instructions hidden in content; hostile or broken input | A check on item text; every tool result marked as untrusted; the engine refuses what it cannot trust | 15 of 15 structural samples caught; subtle ones, such as paraphrases, translations and look-alike letters, are not (0 of 15); 16 of 16 hostile discovery documents refused; 108 of 108 planted faults stopped by the rule written for each; 14 of 14 valid controls pass clean |
| Skills that agents load can carry code | Skill packs hold content only | 6 of 6 hostile skill packs refused (a script, a shebang, a tool allow-list, a path escape) |
| A pattern library is read but not reused | Composing a selection adds what it requires, refuses conflicting pairs and writes starting files | Composition ran on the Systems Graph site (9 files; 12 with the brief) |
| Sites are islands | Sites name each other as peers; agents of three sites call each other through the Open Agentic Web [13], after the visitor's consent | The peer found from either site in 4 requests, where a page crawl reached it only after 10 or 28 pages; each fact attributed to the right site, 8 of 8; the specification authors' own interoperability check passes on all three sites; checkers by four other teams pass on the page with the reader's brief |
| A model in the browser cannot use a site | The same tools in the page through WebMCP [12]; WebAIAssist, a browser extension, gives them to a local model, so the conversation stays on the device | Chrome's built-in model with extension 0.1.1: a tool and a valid answer on 10 of 10 questions; WebMCP conformance 16 of 16 in Chrome; 530 of 536 calls return the same values as the tool server, and the other 6 differ as the specification requires |
| Knowledge locked into one tool or vendor; unclear terms for AI use | Static files on any host; an Apache-2.0 engine; `llms.txt` [2]; instruction files for coding tools; export and re-import; one licence policy in three machine-readable forms | 11 of 11 export and re-import pairs return every item intact; instruction files for 11 coding tools carry identical bytes; the licence is readable in `robots.txt`, a text-and-data-mining reservation and the graph |
| Nobody can tell who wrote what, or whether a model did | Provenance on every item; every merged change in a hash-linked ledger | A changed ledger is among the 33 changes caught |
| Two builds differ, so nothing can be verified | A repeatable build and a conformance suite with four levels; the lowest needs only static files | 560 of 560 files identical across two builds, and under another time zone and locale; 376 test cases pass; the Python checker agrees on the 115 it runs |
| Tools that are hard to start with or to trust | Thirteen task guides; a published crosswalk to eight frameworks, among them the EU AI Act, NIST AI RMF, GDPR and WCAG | 13 of 13 guides run as written; a new site in six commands and 22 seconds, with two failed steps on the way |
| Working without a network, for every reader, at scale | Static files; pages checked for accessibility | 11 of 11 operations work offline; 0 automated (axe-core) violations on 250 pages; 10,000 items built in 119 seconds |
